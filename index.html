01 Why Tandem

Built for the things that only make sense together.

A Tandem is not a token, an account, or a promise from a platform. It is one evolving object controlled by a pair. Its history follows exact rules that any independent implementation can verify.

A

Mutual by design

Every state change requires the current pair. Neither participant acts alone.

B

A history that grows

Each chapter becomes part of one continuous object instead of a scattered trail.

C

The exit comes first

Recovery transactions are prepared and checked before the shared state moves.

04 Clear boundaries

What Tandem is.
What it refuses to become.

It is

  • A deterministic Bitcoin protocol
  • One jointly controlled object
  • An exact sequence of shared actions
  • A recovery path prepared in advance

It is not

  • A marketplace or investment product
  • A token, yield program, or ranking system
  • A platform with an administrator key
  • A guarantee against key loss or misuse
